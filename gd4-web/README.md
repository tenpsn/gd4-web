# GD4 Medical เว็บไซต์และระบบหลังบ้าน

เว็บไซต์บริษัทและระบบหลังบ้านสำหรับแก้ไขเนื้อหา ทำตามแบบในโฟลเดอร์ design
ใช้ Next.js 16, TypeScript และ Tailwind CSS 4

## วิธีรัน

```bash
npm install
cp .env.example .env.local
npm run dev
```

หลังรันแล้วเปิดหน้าเว็บที่ http://localhost:3000 และหน้าหลังบ้านที่ http://localhost:3000/admin

ก่อนรันให้ใส่ค่า AUTH_SECRET และ DATABASE_URL ในไฟล์ .env.local ก่อน
ต้องเปิด PostgreSQL ไว้และสร้างฐานข้อมูลเปล่าไว้ก่อน ระบบจะสร้างตารางให้เองตอนรันครั้งแรก

คำสั่งอื่น
- npm run build สร้างเว็บสำหรับขึ้นใช้งานจริง ตอน build ต้องต่อฐานข้อมูลได้ เพราะหน้าเว็บถูกสร้างล่วงหน้าจากข้อมูลในฐานข้อมูล
- npm run lint ตรวจโค้ด

## ล็อกอินหลังบ้าน

ใช้อีเมลผู้ใช้ทดสอบ เช่น somchai@gdfourmedical.com ซึ่งเป็นผู้ดูแลสูงสุด
รหัสผ่านของผู้ใช้ทดสอบดูได้ในช่อง password ของไฟล์ .data/mock-db.json
ตอนนำเข้าฐานข้อมูล ระบบเข้ารหัสรหัสผ่านก่อนเก็บเสมอ ในฐานข้อมูลจึงไม่มีรหัสผ่านแบบอ่านได้
ก่อนขึ้นเว็บจริงต้องเปลี่ยนรหัสผ่านหรือลบผู้ใช้ทดสอบทั้งหมด

## ฐานข้อมูล

ข้อมูลทั้งหมดเก็บใน PostgreSQL รวมถึงไฟล์ที่อัปโหลด
ฐานข้อมูลในเครื่องชื่อ webgd4 ที่อยู่ฐานข้อมูลใส่ไว้ใน DATABASE_URL ของไฟล์ .env.local

ตารางที่ระบบสร้างให้
- meta เก็บค่าที่มีชุดเดียว เช่น การตั้งค่าเว็บ สิทธิ์ ธีม และงานร่าง
- users, pages, categories, products, messages, activity, media เก็บหนึ่งรายการต่อหนึ่งแถว
- uploads เก็บไฟล์รูป PDF และฟอนต์ที่อัปโหลด

ตอนรันครั้งแรกกับฐานข้อมูลเปล่า ระบบจะนำข้อมูลตัวอย่างในโฟลเดอร์ .data เข้าฐานข้อมูลให้
ถ้าไม่มีโฟลเดอร์นี้จะใช้ข้อมูลตั้งต้นในไฟล์ src/server/seed.ts แทน
ถ้าอยากเริ่มข้อมูลใหม่ทั้งหมด ให้ลบตารางทั้งหมดในฐานข้อมูล webgd4 แล้วรันใหม่

ห้ามอัปโหลดรูปหรือไฟล์ที่มีข้อมูลคนไข้จริงตอนทดสอบ และห้ามเอาข้อมูลจริงใส่ในโฟลเดอร์ .data เพราะโฟลเดอร์นี้ติดไปกับ git

ไฟล์ src/server/store.ts เป็นที่เดียวที่อ่านและเขียนข้อมูล ผ่าน readDb และ mutate
ถ้าเพิ่มข้อมูลชนิดใหม่ ให้แก้ฟังก์ชัน migrate และเพิ่มเลข MIGRATE_REV ระบบจะปรับข้อมูลในฐานข้อมูลให้ครั้งเดียวตอนรัน

## หน้าต่าง ๆ

หน้าเว็บภาษาไทยไม่มีคำนำหน้าในที่อยู่ เช่น /about, /products, /products/pm-12, /service, /contact
หน้าเว็บภาษาอังกฤษขึ้นต้นด้วย /en เช่น /en/about

หน้าหลังบ้าน
- /admin หน้าภาพรวม
- /admin/products สินค้า
- /admin/content เนื้อหาเว็บ
- /admin/design ธีมและตัวอักษร
- /admin/inbox ข้อความจากลูกค้า
- /admin/users ผู้ใช้
- /admin/settings ตั้งค่า

หน้าดูตัวอย่างก่อนเผยแพร่คือ /preview ตามด้วยชื่อหน้า เปิดได้เฉพาะคนที่ล็อกอินแล้ว
ทุกหน้าหลังบ้านตรวจสิทธิ์ผู้ใช้ที่ฝั่งเซิร์ฟเวอร์ทุกครั้ง

## โครงสร้างโฟลเดอร์

- src/app/[lang] หน้าเว็บ
- src/app/admin หน้าหลังบ้าน และ actions ที่บันทึกข้อมูล
- src/app/preview หน้าดูตัวอย่างฉบับร่าง
- src/server ระบบหลังบ้าน เช่น ข้อมูล การล็อกอิน สิทธิ์ และการอัปโหลด
- src/admin หน้าจอหลังบ้าน ข้อความ และตัวแก้ไขเนื้อหา
- src/admin/sectionSchema.ts กำหนดว่าแต่ละส่วนของหน้ามีช่องอะไรให้แก้
- src/lib/content.ts ที่เดียวที่หน้าเว็บอ่านเนื้อหา
- src/lib/designCss.ts แปลงค่าธีมเป็นสีและขนาดบนหน้าเว็บ
- src/components/sections ส่วนต่าง ๆ ของหน้าเว็บ ใช้ทั้งหน้าเว็บจริงและหน้าดูตัวอย่าง

## การเชิญผู้ใช้

เมื่อเพิ่มผู้ดูแล หน้าจัดการผู้ใช้จะแสดงลิงก์เชิญให้คัดลอกไปส่งเอง ลิงก์ใช้ได้ 7 วัน
ลิงก์ใช้ที่อยู่จาก NEXT_PUBLIC_SITE_URL
ถ้าผู้ใช้ลืมรหัสผ่าน ให้ผู้ดูแลสูงสุดลบบัญชีแล้วเชิญใหม่

## การเผยแพร่

ตัวแก้ไขเนื้อหาและธีมบันทึกเป็นฉบับร่างอัตโนมัติ และแสดงในหน้าดูตัวอย่าง
เมื่อกดเผยแพร่ ฉบับร่างจะขึ้นหน้าเว็บจริงทันที
สินค้าเผยแพร่แยกจากหน้าแก้ไขสินค้าเอง

## สิ่งที่ยังไม่ได้ทำ

- ระบบส่งอีเมล ได้แก่ อีเมลเชิญผู้ใช้ ลืมรหัสผ่าน และแจ้งเตือนเมื่อมีข้อความใหม่
- ภาษาอื่นนอกจากไทยและอังกฤษ
- ตั้งตัวอักษรแยกแต่ละส่วนของหน้า
- รูปและโลโก้จริง ลิงก์ YouTube, sitemap และระบบเก็บสถิติ
- หน้านโยบายความเป็นส่วนตัว และแถบขอความยินยอมคุกกี้ เพราะแผนที่ Google ที่ฝังไว้เก็บคุกกี้ของผู้เข้าชม
- หน้ารายละเอียดสินค้ายังไม่มีในแบบ ต้องให้ทีมออกแบบตรวจอีกครั้ง
